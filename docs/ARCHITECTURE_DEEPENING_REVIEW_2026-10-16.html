Fix-as-Code Pull Request Lifecycle & Status Polling Module

~867 lines → 1 deep module

1. Where

2. The Shallow Seam & Live Bug

CloudGuard opens Terraform pull requests in two places: for a security rule across an estate (kind="RULE") and for a choke-point cut on an attack path (kind="CUT"). Both store rows in the exact same FixPullRequest table (models/pull_request.py). Even cut_pull_requests.py:209 delegates claim_due to pull_requests.claim_due(session, kind=KIND_CUT).

Yet everything around that queue is cloned across two ~400-line backend modules and two frontend UI modules:

  • Backend clone: request() (grouping IacStateEntry rows by repo and upserting FixPullRequest), _read_job() (loading IacIndexEntry + GitHub installation), open_on_github() (checking suspended installations, minting installation tokens, fetching HCL files over HTTP, calling open_pull_request), and _settle() (handling OPEN, DECLINED, retry backoff, and FAILED) are written twice.
  • Live UX bug in Attack Paths (HowToFix.tsx:41-55): FixPullRequests.tsx:44-45 sets refetchInterval: 5_000 whenever any PR is in QUEUED or OPENING so the row transitions from "Opening…" to "#42 opened" automatically. HowToFix.tsx omits refetchInterval on cutFixQuery(link) and re-implements prState() at L201-217 — leaving users who click "Open pull request" on an attack path stuck on an infinite "Opening…" spinner until they manually refresh the browser.

CANDIDATE 04 High Leverage Security & RLS Invariant (§54)

Request-Scoped RLS Transaction Ownership Seam

19 route-level commits across 11 files
Database · Security

1. Where

apps/api/app/core/db.py:126-186 — rls_session (SET LOCAL ROLE authenticated + request.jwt.claims)
apps/api/tests/unit/test_request_transaction.py:26, 97-121 — AST guard (currently checks app/services/ only)
apps/api/app/api/routes/remediation.py:47, 137, 179, ownership.py:48, 59, 69, assets.py:272, 283
apps/api/app/api/routes/notifications.py:58, 81, 96, integrations.py:80, 90, scans.py:53, 89, 111

2. The Shallow Seam & RLS Hazard

Per DECISIONS.md §54, rls_session in core/db.py:126-163 wraps every HTTP request in a single PostgreSQL transaction (async with session.begin():) and applies SET LOCAL ROLE authenticated and SET LOCAL request.jwt.claims. test_request_transaction.py enforces via AST inspection that no module under app/services/ calls session.commit().

However, 11 route files under app/api/ still call await session.commit() directly (19 call sites). In PostgreSQL + SQLAlchemy 2.0, calling await session.commit() inside rls_session terminates the transaction early and resets all SET LOCAL GUCs (ROLE and request.jwt.claims) for the rest of the route handler. Any query or lazy read after that commit runs outside the tenant's RLS context!

⚠️ Architectural Constraint Note (DECISIONS.md §54 + Celery Visibility)

16 of the 19 await session.commit() calls in app/api/ are pure historical leftovers at the end of route handlers (and can be deleted outright so rls_session commits on exit). However, 3 call sites (routes/scans.py:53 create_scan, routes/scans.py:89 replay_scan, and routes/findings.py:322 rescan_finding) commit mid-handler specifically so an out-of-process Celery worker (enqueue_or_fail) can see the newly created Scan row immediately. Deepening this seam must preserve out-of-process visibility before Celery dispatch (either via a dedicated commit_and_rebind_rls(session) helper in core/db.py or post-commit dispatch).

3. What Deepening Looks Like

Delete the 16 redundant await session.commit() calls from route handlers so rls_session owns transaction commit uniformly across all routes. Encapsulate the pre-enqueue commit + RLS re-binding for the 3 Celery scan dispatch points inside services/scans.py / core/db.py, and extend tests/unit/test_request_transaction.py to scan app/api/ as well as app/services/.

Cache coherence in the React SPA is currently every caller's personal responsibility, creating both privacy/tenant bleed and 4 concrete stale-screen bugs:

Expose question-level async functions on the graph read module (read_route_map, read_blast_radius, read_access, read_neighborhood, read_estate, read_simulation, read_finding_provenance) that encapsulate the load_graph → NotFound check → SQL enrichment → single off_loop pipeline and make low-level serialize_* helpers module-private.
