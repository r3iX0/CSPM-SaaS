RDP reachable from the internet on prod-vm-01

TCP/3389 accepts connections from 0.0.0.0/0 through the network security group nsg-prod-app. The machine runs the payments API and holds a managed identity with read access to payments-db.

There is no button that marks this fixed. A later scan closes it, or it stays open.

Verified fixed

A scan on Sep 21, 16:41 read nsg-prod-app again and TCP/3389 no longer accepts 0.0.0.0/0. The finding closed itself — nobody marked it.

evidence sha256 4c1f9ab77e02… · network.nsg_rules · read 2026-09-21T16:41:07Z

Why it matters

Anything on the internet can attempt a login against this port. The machine's managed identity can read payments-db, so a successful login reaches customer records without a second step.

How to fix it

Restrict TCP/3389 to your VPN range, then verify. About 10 minutes.

az network nsg rule update \
  --resource-group rg-prod-app \
  --nsg-name nsg-prod-app \
  --name allow-rdp \
  --source-address-prefixes 10.20.0.0/16 \
  --access Allow

Grant read access

Consent let Cleave see which directory you are; this step lets it read what's inside. Run one of these below — every parameter is already filled in, including Cleave's service principal id in your tenant.

Cloud Shell Bicep Terraform 
az role assignment create \
  --assignee-object-id 8f2c4d17-9ab3-4f51-bd0e-7c1e2a6f9d44 \
  --assignee-principal-type ServicePrincipal \
  --role "Cleave Reader" \
  --scope /providers/Microsoft.Management/managementGroups/acme-root

What the role can do

  • Exactly the read operations the collector performs — no */action entries at all.
  • Generated from the connector, so a test fails if the two ever disagree.
  • Azure's built-in Reader works too, if you would rather not add a custom role.
